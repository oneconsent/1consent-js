# @1consent/nextjs

Next.js 16 adapter for the 1Consent React integration. It exposes the same
components and hook as `@1consent/react`, preserves React Server Component
boundaries for the App Router, and adds an isolated server entrypoint for
validated consent-cookie hints.

## Distribution status

Stable releases are published on npm's `latest` dist-tag; prereleases use the
`beta` dist-tag. The protected public-repository workflow stages each release
with provenance for a maintainer's npm 2FA approval, using trusted publishing.

```sh
npm install @1consent/nextjs
```

## App Router

Server Components can render the provider and consent gates directly:

```tsx
import { OneConsentProvider } from "@1consent/nextjs";
// Written by `npx @1consent/cli typegen --app YOUR_APP_ID`.
import { fastPathVersions } from "@/1consent.gen";

export default function RootLayout({ children }: { children: React.ReactNode }) {
    return (
        <html lang="en">
            <body>
                <OneConsentProvider appId="YOUR_APP_ID" fastPathVersions={fastPathVersions}>
                    {children}
                </OneConsentProvider>
            </body>
        </html>
    );
}
```

Wrap third-party markup in `OneConsent` (also importable in Server Components)
to keep it inert until the named service or category has consent.

`useConsent` is a client hook and must be imported from a Client Component:

```tsx
"use client";

import { useConsent } from "@1consent/nextjs";

export function AnalyticsStatus() {
    const granted = useConsent("Google Analytics");
    return <span>{granted ? "enabled" : "disabled"}</span>;
}
```

## Execution timing

Pass the framework-associated `fastPathVersions` generated by `1c typegen`
and load the provider before governed resources. With a valid returning-visitor
mirror, a complete gate activates when its parse-time resolver runs, without
waiting for the asynchronous CMP runtime. Inline code runs synchronously when
no ordinary external dependency is pending. Ordinary external classic scripts
and their following instructions retain dependency order across gates;
explicit async/defer/module choices keep their nonblocking semantics.

This is an execution-order and consent guarantee, not a universal first-paint
deadline. Streamed content can paint before a later gate arrives, and permitted
external downloads can finish after paint. The integration does not hold page
rendering while waiting for vendors. Missing, expired or stale consent remains
inert until the CMP establishes current permission. SPA gates activate through
the inline engine's observer after mounting; they have no initial-paint promise.

## Server helpers

The explicit server entrypoint reads the `1consent` cookie only when it matches
the complete scope you pass and its legal expiry has not passed:

```ts
import { COOKIE_NAME, parseConsentCookie, readConsentCookie } from "@1consent/nextjs/server";

// "A" (all accepted), "D" (all denied), "G" (granular) or "none".
const decision = parseConsentCookie(cookieValue, expected);
// The full validated cookie, or null.
const cookie = readConsentCookie(cookieValue, expected);
```

`expected` is a `ConsentCookieExpectation`: `appId`, `frameworkId`,
`frameworkType`, `machine`, `primaryLanguage`, `structuralVersion` and
`consentEpoch` of the configuration the request is served with. A cookie from
another app, framework, language, structural version or consent epoch, or one
past its expiry, reads as `"none"` / `null`.

Reading `cookies()` inside a Server Component makes the route dynamic. For
static pages, use the helper from a Proxy or Route Handler and pass the cookie
value explicitly. A cookie result is only a server-side hint; it does not
replace authoritative client-side consent enforcement.

## Before publication

The adapter depends on the matching React package. From this repository's
root, pack both reviewed artifacts into an existing directory:

```sh
npm pack ./packages/libs/react --pack-destination /path/to/tarballs
npm pack ./packages/libs/nextjs --pack-destination /path/to/tarballs
```

Install both tarballs together in a Next.js 16 test project with React and
React DOM 19. This repository contains distribution artifacts rather than
the private source build.
